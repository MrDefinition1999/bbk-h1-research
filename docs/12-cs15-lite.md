# CS15 Lite 参考与 H1 重建状态

更新日期：2026-08-04

本页只记录 CS15 Lite 参考项目以及 H1 重建时可以复用的工程经验。9588 的
可执行文件、资源包和 ABI 不能直接作为 H1 发布输入；H1 使用 JZ4740、不同
分辨率和不同 BDA 服务表，必须重新编译并逐项验证。

## 参考项目

公开参考源码位于 `references/CS15-Lite-for9588/`，上游为
`HelloClyde/CS15-Lite-for9588`。该项目是面向 BBK 9588 的低内存、定点数、
单机 Counter-Strike 1.5 风格运行时，资源由离线工具转换为紧凑包，运行时不
依赖 GoldSrc ELF 或完整桌面引擎。其可借鉴的原则包括：

- 地图、碰撞、PVS、贴图和模型在离线阶段压缩，运行时按地图建立有界 arena；
- 使用定点数和 RGB565 直接写 framebuffer，避免整帧旋转和临时大缓冲；
- 音效使用小块流式读取和固定大小 scratch，避免 FAT 随机访问造成卡顿；
- 构建脚本固定 `-Os`、section garbage collection 和静态镜像上限；
- 资源包带版本标记，版本不匹配时拒绝进入地图，避免错误布局导致死机。

## H1 适配边界

H1 的独立 SDK 位于 `h1-bda-sdk/`。已确认的 H1 公共能力和调用约定只应从
`h1-bda-sdk/sdk/include/` 及其 `reverse/docs/` 文档使用，不得复制 9588 的
地址常量、服务表布局或输入码。当前确认项包括：

- MIPS32 little-endian 平面 BDA 加载模型；
- H1 图形 RGB565 矩形绘制、回读和 present；
- 全键盘队列、单调 tick 和定时器；
- 受限文件、内存和对话框 API。

H1 显示屏不是 9588 的 320x240 布局。移植时应以 H1 framebuffer 的实际宽高
和触摸坐标为准，使用等比视口并在剩余区域留黑边；输入应同时支持 H1 实体
全键盘与触摸事件。

## 当前重建结论

磁盘事故后，公开 CS15 参考树已恢复并保存在 `references/CS15-Lite-for9588/`。
原 H1 专用 CS15 BDA、H1 资源包和实机测试包没有可信副本，不能从历史失败
产物恢复或发布。工作区中的同名历史包只作为损坏证据，不作为构建输入。

因此当前状态是：

1. 参考项目可用于研究资源格式、定点渲染、输入和音频策略；
2. 尚未确认一个可在 H1 实机运行的 CS15 BDA；
3. 重新实现需要可信 H1 固件/SDK 输入，并需要用户合法持有的 CS 资源；
4. 完成后必须在 H1 模拟器和实机分别验证启动、地图加载、输入、音频、退出
   和资源包版本拒绝路径。

## 建议的 H1 实现顺序

先用无版权资源建立 H1 的最小地图、输入和 RGB565 渲染探针，再加入资源包
版本头和固定内存配额；之后逐项加入碰撞、AI、音频和触摸视角。每个阶段的
真机包应放入独立的 H1 游戏槽，不覆盖原有应用。发布包只包含 `A-root`、BDA
和 `应用\\数据` 下的资源，不包含源码缓存、调试日志或本机路径。

## 隐私与发布检查

CS15 资源包可能包含用户自行提供的商业素材。发布前只打包已获授权的资源，
并运行：

```powershell
python scripts/audit_release_secrets.py <archive>
```

审计归档本身；任何用户名、主机名、绝对路径、凭证、私钥、日志和缓存命中都
是发布阻断项。
